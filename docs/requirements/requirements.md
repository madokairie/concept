# ローンチコンセプト設計ツール - 要件定義書

## 概要

オンラインコンテンツ販売におけるローンチコンセプトを設計するための、まどか専用AIツール。
けんさんメソッド（完成型ファースト × 3素材収集 × 評価ループ）を基盤とし、
チャット壁打ち形式でAIと対話しながらコンセプトを固める。

自分のローンチとクライアントのローンチ（設計・壁打ち支援）の両方を管理する。

## ユーザー

- **まどか（単一ユーザー）**
- 自分のローンチ: コンセプト設計〜コピー作成まで
- クライアントのローンチ: Zoom画面共有しながら壁打ち、ヒアリングシート活用

## コア機能

### 1. チャット壁打ち（メインUI）

AIと対話しながらコンセプトを設計する。フォーム入力ではなく、
会話の中からAIが必要な情報を引き出し、右サイドパネルに自動で構造化する。

**体験フロー:**
1. プロジェクトを作成（自分 or クライアント名を選択）
2. チャットで壁打ち開始
3. AIが質問しながら各Phaseの情報を引き出す
4. 右パネルにPhase別の情報が自動整理される
5. 各Phaseの情報が揃ったら評価ループを実行
6. コンセプトシートとして出力

**AIの振る舞い:**
- 会話から各Phaseに該当する情報を自動分類
- 足りない情報を自然な流れで質問返し
- 過去の素材ライブラリを参照して提案
- スタイルシート（口調）を常に適用
- 「そのまま使える」レベルのコピーを出力

**Zoom壁打ち時の使い方:**
- まどかが画面共有しながらクライアントと対話
- クライアントの発言をまどかがチャットに入力（or 要約入力）
- AIがリアルタイムで右パネルに整理
- ヒアリングシートの回答をチャットに貼り付け → AI が自動振り分け

### 2. プロジェクト管理

複数のローンチを管理する。

**プロジェクト属性:**
- プロジェクト名
- 種別: 自分のローンチ / クライアントワーク
- クライアント名（クライアントワークの場合）
- ステータス: 設計中 / コンセプト確定 / ローンチ済み / 結果記録済み
- 作成日
- スタイル: まどかデフォルト / クライアント別上書き

**一覧画面:**
- プロジェクトの一覧表示
- ステータスでフィルタ
- 直近のプロジェクトが上に来る

### 3. コンセプト設計フロー（Phase 0〜2）

チャット壁打ちを通じて、以下のPhaseを進める。
順番は固定ではなく、会話の流れに応じてAIが柔軟に対応する。

#### Phase 0: ゴール定義（完成型ファースト）

**収集する情報:**
- 今回のローンチで達成したいこと（定量目標）
- 販売する商品・価格帯
- ローンチ期間・スケジュール感
- 今回のローンチの特徴・新しい点

**AIの処理:**
- 「合格基準チェックリスト」を自動生成
- 必要な変数リストを洗い出し
- 足りない情報があれば質問返し
- 過去のローンチ結果があれば参照して目標の妥当性をコメント

**出力: ゴール定義シート**

#### Phase 1-A: ターゲットインサイト

**収集する情報:**
- ターゲットの現在の状況
- 悩み・感情
- 本音の言葉（実際のDM・お客さんの声）
- 買わない理由・反論
- 深層心理（口には出さない本音）

**AIの処理:**
- 入力からターゲットの「得たい欲求」と「避けたい欲求」を整理
- 「口には出さないが心で思っていること」を補完
- 素材ライブラリの過去のお客さんの声と照合
- 類似ターゲットの過去プロジェクトがあれば参照

**出力: ターゲットインサイトシート**

#### Phase 1-B: パーソナル情報

**収集する情報:**
- 演者の経歴・バックグラウンド
- 強み・得意なこと
- 価値観・こだわり
- 実績・数字
- セミナー文字起こし・過去の発信

**AIの処理:**
- 文字起こしからパーソナル情報を自動抽出
- 「この人だから信頼できる理由」をストーリー形式で整理
- 自分のローンチ → まどかの情報は素材ライブラリから自動参照
- クライアント → ヒアリングシート or チャット入力から収集

**出力: パーソナリティシート**

#### Phase 1-C: スタイルシート

**収集する情報:**
- 使わない言葉・フレーズ（NG表現）と理由
- 使いたい口調・言い回し
- 目線設定（誰に向けて話しているか）
- 自然体の話し方がわかる素材

**AIの処理:**
- スタイルガイドを生成（OK/NG判定ルールセット）
- 以降の全出力にこのスタイルを適用
- まどかのローンチ → デフォルトスタイル自動適用
- クライアント → クライアント別スタイルを生成・保存

**出力: スタイルシート**

**スタイルの階層構造:**
```
グローバル: まどかのデフォルトスタイル（常に適用）
  └─ プロジェクト別: クライアントのスタイルで上書き（任意）
```

#### Phase 2: コンセプト設計

**収集する情報:**
- この商品でなければいけない理由（競合との差別化）
- 今このタイミングで売る理由
- 買わないことで失うもの

**AIの処理:**
- Phase 0〜1の全情報を統合
- コンセプト候補を5案生成 → まどかが選択
- 選んだ案をもとに以下を作成:
  - メインコピー
  - サブコピー
  - 認知の上書きフレーム
  - 解決策のMECE分解
- スタイルシートに準拠した表現で出力

**出力: コンセプトシート**

### 4. 評価ループ（全Phase共通）

各Phaseの出力に対してAIが批判的評価を実行し、修正する。

**評価軸（6項目）:**
1. ターゲットの本音の言葉と一致しているか
2. スタイルシートのNG表現が使われていないか
3. 一般論になっていないか（上位10%の視点があるか）
4. AI臭さが残っていないか（場面・行動・セリフ・感情の4要素があるか）
5. コンセプトと一貫しているか
6. 読んだ人が次のステップに進みたくなるか

**実行タイミング:**
- 各Phase完了時に自動実行
- チャット中にリアルタイムでサイドバーにスコア表示
- 基準未満なら修正提案を自動生成

### 5. 素材ライブラリ

まどかの過去の素材を蓄積・AIが参照する永続レイヤー。

**取り込み対象:**
- 過去のLINE配信文（テキスト/PDF）
- LP原稿（テキスト/PDF）
- セミナー文字起こし（テキスト/PDF）
- お客さんの声（テキスト/PDF）
- ヒアリングシート回答

**取り込み方法:**
- フォルダからファイルを一括アップロード
- AIが自動で種別を判定（LINE配信 / LP / セミナー / お客さんの声 / その他）
- まどかが確認・修正
- 現時点では成功事例がメイン。失敗事例は今後のローンチで蓄積

**AIの活用方法:**
- コンセプト設計時に類似事例を自動参照
- 「この表現、過去のLPで反応良かったやつに近いね」等の提案
- スタイルシートの精度向上（実際の文章から口調パターンを学習）

### 6. 結果記録

ローンチ終了後に実績数字を記録し、次のローンチに活かす。

**記録する数字:**
| 指標 | 必須/任意 | 用途 |
|------|----------|------|
| リスト登録数 | 必須 | コンセプトの刺さり具合 |
| 申込数 | 必須 | オファーの強さ |
| CVR（登録→申込） | 自動計算 | 全体効率 |
| 売上 | 必須 | 最終成果 |

**AIの活用方法:**
- 次のプロジェクトのPhase 0で過去実績を自動参照
- 「前回は登録500→申込30（CVR 6%）。今回の目標CVR 8%なら登録数を増やすか、教育を変えるか」
- プロジェクト横断で「このコンセプトの型はCVRが高い傾向」等のパターン提案

### 7. コンセプトシート出力

壁打ちの結果を整理されたドキュメントとして出力する。

**出力内容:**
- ゴール定義シート（合格基準・必要変数リスト）
- ターゲットインサイトシート（得たい欲求・避けたい欲求・本音の言葉）
- パーソナリティシート（権威性・共感ポイント・ストーリーライン）
- スタイルシート（NG表現一覧・OK表現一覧・口調ガイドライン）
- コンセプトシート（メインメッセージ・認知上書きフレーム・解決策MECE）

**出力形式:**
- アプリ内表示（右サイドパネル）
- PDF出力
- テキストコピー（他ツールへの貼り付け用）

## スコープ外（やらないこと）

- ファネル設計（別アプリで対応）
- タスク・スケジュール管理
- クライアントが直接ログインして使う機能
- LINE/メール配信の実行
- LP作成・公開機能
- 決済・課金機能

## 技術要件

- フロントエンド: Next.js + Tailwind CSS
- AI: Claude API（長文コンテキスト対応）
- DB: Supabase（認証 + データ + ファイルストレージ）
- PDF処理: PDF解析ライブラリ（素材取り込み用）
- 出力: PDF生成 + テキストコピー

## 非機能要件

- まどか専用のためマルチテナント不要
- 素材ライブラリのファイルは安全に保管（Supabase Storage）
- チャット履歴はプロジェクトごとに保存
- レスポンシブ対応（PCメイン、タブレットでも使える程度）
