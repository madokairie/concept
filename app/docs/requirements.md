# ローンチコンセプト設計ツール — 要件定義書

## 1. プロダクト概要

### 1.1 目的
オンラインコンテンツ販売（講座・コンサル・サービス等）のローンチに必要な「コンセプト設計」を、AIとの壁打ち（対話）形式で完成させるWebアプリケーション。

### 1.2 解決する課題
- ローンチ設計に必要な情報（ゴール、ターゲット、コピー、発信戦略等）が整理できていない
- 壁打ち相手がいないと設計が進まない
- 設計した内容がバラバラで一覧性がない
- コンセプトシートの作成に時間がかかる

### 1.3 ユーザー
- 個人事業主・フリーランス（講座ビジネス、コンサル、コーチング等）
- 1人で使用（シングルユーザー想定）
- 自分のローンチ＋クライアントワーク両方に対応

### 1.4 提供価値
- AIが「リード役」として壁打ちを主導し、10-20往復でコンセプト設計を完成
- 対話で出た情報がリアルタイムで整理・構造化される
- プロフェッショナル品質のコンセプトシートPDFを自動生成
- 過去の素材（LP、LINE配信文、セミナー文字起こし等）をAIが参照して具体的に提案

## 2. 機能要件

### 2.1 プロジェクト管理

#### 2.1.1 プロジェクト作成
- プロジェクト名を入力して作成
- 種別選択: 「自分のローンチ」or「クライアントワーク」
- クライアントワークの場合はクライアント名を入力
- スタイルモード自動設定: 自分→デフォルト / クライアント→カスタム

#### 2.1.2 プロジェクト一覧
- 設計中 / ローンチ済みの2グループで表示
- ステータス色分け表示（設計中=ゴールド, 確定=ブルー, ローンチ済=グリーン, 結果記録済=パープル）
- 更新日表示
- プロジェクト削除（確認ダイアログあり）

#### 2.1.3 プロジェクト複製
- 既存プロジェクトをテンプレートとして複製
- 複製時に新しい名前を入力
- Phase データ・設定は引き継ぐが、チャット履歴は引き継がない
- ステータスは「設計中」にリセット

#### 2.1.4 並び替え・フィルター
- 並び替え: 更新日順 / 作成日順 / 名前順
- フィルター: 全て / 設計中 / コンセプト確定 / ローンチ済み / 結果記録済み

#### 2.1.5 ステータス管理
- ステータス遷移: 設計中 → コンセプト確定 → ローンチ済み → 結果記録済み
- ヘッダーのボタンでワンクリック切替
- 「ローンチ済み」にすると結果記録ボタンが出現

### 2.2 AI壁打ちチャット

#### 2.2.1 チャット基本機能
- ユーザーメッセージ送信（Enter送信、Shift+Enterで改行）
- AIレスポンスのストリーミング表示（リアルタイムで文字が流れる）
- Markdown対応（見出し、リスト、太字、テーブル等）
- エラー時の日本語メッセージ表示

#### 2.2.2 AIの行動原則（最重要）
AIは「聞き役」ではなく「コンセプト設計のリード役」として振る舞う:
- **提案7割・質問3割**のバランス
- **仮説ファースト**: 質問だけで終わらず、素材ライブラリや過去データから仮説を立てて確認する
- **たたき台を出す**: 情報が6割集まったら不完全でもアウトプットを出す
- **選択肢を出す**: 「A案とB案どっち？」のように判断を求める
- **素材を使い倒す**: ライブラリの過去データを積極的に引用
- **ゴールを見せ続ける**: 現在地と残りステップを毎回表示

#### 2.2.3 Phase進行ルール
- 各Phase 2-3往復で完了（全体10-20往復が目標）
- 3往復聞いてまだ同じPhaseにいたら、持っている情報だけでたたき台を出して次へ
- Phase完了時は出力シートを生成 +「次はPhase X」+ 仮説or選択肢を一緒に出す
- 毎回の応答末尾に現在地表示（📍マーカー）

#### 2.2.4 チャット検索
- ヘッダーの検索アイコンで検索バーを表示
- キーワードでチャット履歴をフィルタリング
- マッチしたメッセージのみ表示 + ハイライト

#### 2.2.5 Phaseタグ表示
- AIメッセージの📍マーカーからPhaseを自動検出
- メッセージにPhaseバッジを表示（色分け）

#### 2.2.6 URL読み取り
- チャット入力欄にURLを貼ると📎ボタンが出現
- クリックするとサーバーサイドでURLの内容を取得・テキスト化
- 取得したテキストが入力欄に追加される（競合LP分析等に使用）

### 2.3 Phase構造（コンセプト設計フロー）

全5フェーズでコンセプト設計を完成させる:

#### Phase 0: ゴール定義（完成型ファースト）
「何が達成されていれば合格か」を先に定義する。
- 売上目標・申込数の具体的数値
- 商品・サービス名、提供形態、期間、価格
- ローンチスケジュール（セミナー日、販売期間、締切）
- 申込導線（直接購入 / 個別相談経由 / 審査フォーム等）
- 稼働限界（セミナー登壇数、個別面談上限）
- 過去データ（リスト数、CVR、過去売上）

#### Phase 1-A: ターゲットインサイト
- 理想顧客像（ペルソナ: 年齢・職業・状況）
- 深い悩みTOP3（表面ではなく根深い課題）
- 感情トリガーワード
- 入り口キーワード（SNS発信で刺さる言葉）
- 買わない理由・反論
- 深層心理

#### Phase 1-B: パーソナル情報
- 講師プロフィール（名前、肩書き、ブランド名）
- 各SNSフォロワー数
- 代表的な成果・顧客成功事例
- 差別化要因
- 自分のローンチの場合: 素材ライブラリから自動生成→確認のみ

#### Phase 1-C: スタイルシート
- 出したい雰囲気・トーン
- OK表現 / NG表現
- 世界観キーワード
- 自分のローンチの場合: デフォルトスタイル自動適用→変更点のみ確認

#### Phase 2: コンセプト設計
AIが生成:
- コンセプト候補5案 → ユーザーが選択
- メインコピー・サブコピー
- コンセプト方向性
- 認知の上書きフレーム（Before/After）
- 課題点・リスクと対策
- 発信戦略（媒体別・具体的投稿テーマ案付き）
- 発信スケジュール
- KPI設定

### 2.4 Phase情報の自動抽出

#### 2.4.1 phase_update機構
- AIがチャットの中からPhaseに該当する情報を自動検出
- レスポンス末尾にJSON形式で構造化データを付与
- UIには表示されず、システムが自動的にPhaseデータを更新
- 各PhaseのstatusをAIが自動的に `pending` → `in_progress` → `completed` に更新

#### 2.4.2 抽出データ構造
```json
{
  "phase": "phase0",
  "status": "completed",
  "data": { "revenue_target": "500万円", "product": "プロモーター養成講座" },
  "output": "### 売上目標\n- 目標売上: 500万円...",
  "evalScore": { "targetMatch": 9, "styleCompliance": 8, ... }
}
```

### 2.5 サイドバー

#### 2.5.1 プロジェクト情報
- プロジェクト名、種別表示

#### 2.5.2 Phaseパネル
- 全5Phaseの進捗表示（○未着手 / ●進行中 / ✓完了）
- クリックで展開/折りたたみ
- データ項目数の表示
- 各項目の日本語ラベル表示（英語キー → 日本語変換）
- 項目値のプレビュー（100文字まで）
- outputの表示（500文字まで）

#### 2.5.3 Phase編集
- 各データ項目にホバーで✏️ボタン表示
- クリックでインライン編集モード
- テキストエリアで直接編集→保存/キャンセル

#### 2.5.4 評価スコア
- 6軸の評価バー表示:
  - 本音一致（ターゲットの本音の言葉と一致しているか）
  - スタイル準拠（NG表現が使われていないか）
  - 独自性（一般論になっていないか）
  - 自然さ（AI臭さがないか）
  - 一貫性（コンセプトとの一貫性）
  - 行動喚起（次のステップに進みたくなるか）
- 各軸1-10のスコア
- 平均スコア表示

#### 2.5.5 コンセプトシート生成・出力
**2段階のフロー:**
1. **「コンセプトシート生成」ボタン**: チャット履歴全体をAIに送信し、プロフェッショナルな構造化HTMLを生成
2. **「PDF出力」ボタン**: 生成されたHTMLをCSSで包んで新しいウィンドウで印刷

### 2.6 コンセプトシートPDF

#### 2.6.1 品質基準
提案書・企画書レベルのプロフェッショナルな見た目:
- カバーページ（プロジェクト名、種別、日付）
- Phase別セクション（ゴールドの帯見出し）
- kv-gridレイアウト（ラベル:値のグリッド）
- カード形式（ペルソナ、媒体別戦略）
- 2カラムレイアウト（OK/NG表現、実績比較）
- タグピル（感情キーワード、世界観キーワード）
- テーブル（スケジュール、Before/After、投稿タイミング）
- メインコピーの大きな表示（左ボーダー+背景色）
- 課題・リスクの赤ボーダーカード
- 発信戦略の媒体別カード（具体的投稿テーマ案付き）
- 評価スコアのバー表示セクション

#### 2.6.2 コンテンツ要件
- チャットで議論された**具体的な内容**をすべて含める
- 投稿テーマ案、リール構成案、数字、スケジュールを漏れなく入れる
- 次の投稿作成の指示書として使えるレベル
- 完全日本語（英語キー名は使わない）

### 2.7 素材ライブラリ

#### 2.7.1 素材管理
- ファイルアップロード（.txt, .md, .pdf, .csv対応）
- カテゴリ自動判定（ファイル名から推定）
- カテゴリ: LINE配信 / LP / セミナー / お客さんの声 / その他
- カテゴリ手動変更
- 素材削除
- カテゴリ別フィルター

#### 2.7.2 一括インポート
- 指定フォルダからテキストファイルを一括読み込み
- 既存の素材と重複チェック（ファイル名ベース）
- 初回アクセス時に自動シード

#### 2.7.3 AI参照
- チャット時にAIのシステムプロンプトに素材内容を含める
- 最新5件の素材スニペット（各500文字まで）を提供
- AIが過去のLP文言やメールキャンペーンを引用して具体的に提案

### 2.8 結果記録（フィードバックループ）

#### 2.8.1 結果入力
- ステータスが「ローンチ済み」のプロジェクトで利用可能
- 入力項目: リスト数（セミナー参加者数）、申込数、売上（円）
- CVR自動計算（申込数 ÷ リスト数 × 100）

#### 2.8.2 結果表示
- プロジェクト一覧に結果サマリー表示（CVR、売上）
- モーダルで詳細表示（4カード: リスト数、申込数、CVR、売上）
- 記録日表示

### 2.9 デフォルトスタイル

#### 2.9.1 スタイル定義
ユーザー固有のコミュニケーションスタイルを定義:
- 口調（丁寧語ベース、くだけた表現等）
- OK表現（使ってほしい言い回し）
- NG表現（絶対に使わない表現とその理由）
- 立ち位置（先生感を出さない等）
- 冒頭の入り方（読者のあるあるから入る等）
- 必ず入れる要素（数字、共感、リアルな恐怖の言語化等）

#### 2.9.2 適用ルール
- 「自分のローンチ」→ デフォルトスタイル自動適用
- 「クライアントワーク」→ Phase 1-Cで個別に収集

## 3. 非機能要件

### 3.1 技術スタック
| 項目 | 技術 |
|------|------|
| フレームワーク | Next.js 16（App Router） |
| UI | React 19 + TypeScript |
| スタイリング | Tailwind CSS v4 |
| AI | Anthropic Claude API（Sonnet 4）|
| ストレージ | ブラウザ localStorage |
| アイコン | Lucide React |
| Markdown | react-markdown |

### 3.2 データ永続化
- **ブラウザのlocalStorage**を使用（サーバーDB不要）
- キー構造:
  - `concept_projects`: プロジェクト一覧
  - `concept_messages`: プロジェクト別チャット履歴
  - `concept_materials`: 素材ライブラリ
  - `concept_default_style`: デフォルトスタイル

### 3.3 AI連携
- Anthropic Claude API（ストリーミング対応）
- モデル: claude-sonnet-4-20250514
- max_tokens: 4096（チャット）/ 8192（コンセプトシート生成）
- システムプロンプト: 約300行（Phase構造・行動原則・評価基準を含む）

### 3.4 デザイン
- ダークテーマ
- 背景: #0D0D0D
- テキスト: #E8E0D5
- アクセントカラー: #C8A96E（ゴールド）
- フォント: Georgia, Noto Serif JP（serif系）
- 高級感のあるミニマルデザイン

### 3.5 動作環境
- モダンブラウザ（Chrome, Safari, Firefox, Edge）
- Node.js 18以上（開発・ビルド時）
- ローカル実行（localhost:3900）

## 5. データモデル

### 5.1 Project
```typescript
{
  id: string;              // UUID
  name: string;            // プロジェクト名
  type: 'self' | 'client'; // 種別
  clientName?: string;     // クライアント名（clientの場合）
  status: 'designing' | 'concept_fixed' | 'launched' | 'result_recorded';
  styleMode: 'default' | 'custom';
  createdAt: string;       // ISO 8601
  updatedAt: string;       // ISO 8601
  phases: PhaseData;       // 5つのPhase情報
  results?: LaunchResult;  // ローンチ結果
}
```

### 5.2 PhaseData
```typescript
{
  phase0: PhaseInfo;   // ゴール定義
  phase1a: PhaseInfo;  // ターゲットインサイト
  phase1b: PhaseInfo;  // パーソナル情報
  phase1c: PhaseInfo;  // スタイルシート
  phase2: PhaseInfo;   // コンセプト設計
}
```

### 5.3 PhaseInfo
```typescript
{
  status: 'pending' | 'in_progress' | 'completed';
  data: Record<string, string>;  // 構造化データ
  output?: string;               // Phase完了時の出力テキスト
  evalScore?: EvalScore;         // 評価スコア
}
```

### 5.4 EvalScore
```typescript
{
  targetMatch: number;      // 1-10
  styleCompliance: number;  // 1-10
  originality: number;      // 1-10
  humanLike: number;        // 1-10
  consistency: number;      // 1-10
  actionDriving: number;    // 1-10
}
```

### 5.5 ChatMessage
```typescript
{
  id: string;
  role: 'user' | 'assistant';
  content: string;
  timestamp: string;
  phaseTag?: string;  // 関連Phase
}
```

### 5.6 MaterialFile
```typescript
{
  id: string;
  name: string;
  category: 'line' | 'lp' | 'seminar' | 'voice' | 'other';
  content: string;
  uploadedAt: string;
}
```

### 5.7 LaunchResult
```typescript
{
  listCount: number;         // リスト登録数
  applicationCount: number;  // 申込数
  cvr: number;              // CVR（自動計算）
  revenue: number;          // 売上
  recordedAt: string;       // 記録日
}
```

## 6. カスタマイズポイント

他のユーザーが自分用にカスタマイズする際に変更が必要な箇所:

| ファイル | 変更内容 |
|---------|---------|
| `.env.local` | 自分のAnthropic APIキーを設定 |
| `src/lib/default-style.ts` | 自分のコミュニケーションスタイルに書き換え |
| `src/lib/prompt.ts` | 「まどかさん」→ 自分の名前に変更 |
| `src/app/api/import-materials/route.ts` | 自分の素材フォルダのパスとファイル一覧に変更 |

詳細は `docs/setup-guide.md` を参照。
